## Contributing

Thanks for wanting to help. A few things to keep in mind:

- **Never commit game files.** That includes anything from `assets/original/`, disk images,
  decoded graphics or sound dumps, and exported builds. If a bug needs data to reproduce, describe
  where in the game it happens instead.
- **No hard-coded paths.** Everything is found at runtime (command line, environment, saved setting,
  folder next to the project/executable, or the file dialog).
- Keep it faithful. The goal is to play like the original; behaviour comes from the game's own data and
  rules, not from guesses.
- Match the style of the code around you. GDScript uses tabs and static types.

For bugs, say what you did, what you expected and what happened, plus which level. A screenshot helps.
